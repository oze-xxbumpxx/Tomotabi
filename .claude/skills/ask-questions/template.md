# 問いのひな形

問いは論点の記録（`docs/discussions/<機能名>.md`）に書く。記録全体の形は`docs/discussions/README.md`、実例は`docs/discussions/discussion-workflow.md`。

## 論点の記録に書くとき

```markdown
### <具体的な問い（1文）>

<!-- id: <英小文字とハイフンの機械用の名前> -->

- 工程: 要件 | 設計 | 実装 | 運用
- 優先度: 高 | 中 | 低
- 状態: 回答待ち | 仮決定 | 後の工程へ
- なぜ今: <答えが無いと何を書けないか>
- 根拠: <正本の箇所 / path:line / ADR>
- 選択肢:
  - A) <選択肢>
    - 利点: <1文>
    - 欠点: <1文>
  - B) <選択肢>
    - 利点: <1文>
    - 欠点: <1文>
- 推奨: B（<推奨の理由を1文>）
```

## 例（支払い・精算の中核で出せた問い）

```markdown
### 精算の確認を取り消したあと、同じ確認をもう一度「完了」にできるか

<!-- id: reconfirm-after-cancel -->

- 工程: 設計
- 優先度: 高
- 状態: 回答待ち
- なぜ今: できるかどうかで、受け渡しの確認の状態の移り方と、画面に出すボタンが変わる。
- 根拠: 詳細設計の精算の状態の節は「取り消し」までで、その後を書いていない。
- 選択肢:
  - A) できる（取り消しの前に戻す）
    - 利点: 押し間違えた人がすぐ戻せる
    - 欠点: 取り消した記録が上書きされ、誰が何をしたかを追えない
  - B) できない。新しい確認を作り直す
    - 利点: 取り消した記録が残る
    - 欠点: 作り直す手間が1回増える
- 推奨: B（取り消した記録が残り、二人のどちらが何をしたかを後から追える）
```

## 答えをもらったあと

状態を「決定」にして、次の行を足す。

```markdown
- 決定: B
- 推奨と同じか: 同じ
- 理由:
- 選ばなかった理由: A（取り消した記録を上書きすると、二人のどちらが何をしたかを後から追えなくなるため）
- 反映先: docs/designs/payments-and-settlement.md「精算の状態の移り方」
- 決めた日: 2026-10-01
```

## チャットだけで出すとき（ページが使えないとき）

```markdown
<機能の名前> の <工程> を書く前に、決めてほしいことが <N> 問あります。
「1A 2B」のように記号で答えてください。推奨どおりなら「全部推奨」で進めます。

### 1. <問い>

- なぜ今: <…>
- 推奨: A
  - A) <選択肢>（推奨。利点 / 欠点）
  - B) <選択肢>（利点 / 欠点）
  - C) その他（自由に書く）
```
