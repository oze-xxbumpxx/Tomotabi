# 問いのひな形

## ユーザーに出すとき（今の工程・優先度: 高 だけ）

```markdown
<機能の名前> の <工程> を書く前に、決めてほしいことが <N> 問あります。
「1A 2B」のように記号で答えてください。推奨どおりなら「全部推奨」で進めます。
ほかに <M> 問を、後の工程で決める問いとして未決事項に残しました。

### 1. <具体的な問い（1 文）>

- なぜ今: <答えが無いと何を書けないか>
- 根拠: <正本の箇所 / path:line / ADR>
- 推奨: A
  - A) <選択肢>（推奨。<推奨の理由を 1 文>）
  - B) <選択肢>（<何が変わるか>）
  - C) その他（自由に書く）
```

## 例（支払い・精算の中核で出せた問い）

```markdown
### 1. 精算の確認を取り消したあと、同じ確認をもう一度「完了」にできるか

- なぜ今: できるかどうかで、受け渡しの確認の状態の移り方と、画面に出すボタンが変わる。
- 根拠: 詳細設計の精算の状態の節は「取り消し」までで、その後を書いていない。
- 推奨: B
  - A) できる（取り消しの前に戻す）
  - B) できない。新しい確認を作り直す（推奨。取り消した記録が残り、二人のどちらが何をしたかを後から追える）
  - C) その他（自由に書く）
```

## 未決事項に残すとき（それ以外）

```markdown
| 問い   | 工程 | 優先度 | 推奨   | 根拠   |
| ------ | ---- | ------ | ------ | ------ |
| <問い> | 設計 | 中     | <推奨> | <根拠> |
```

## 記録するとき（答えをもらったあと）

```markdown
## 決めたこと（問いと答え）

| 問い                                   | 答え               | 推奨と同じか | 理由（ユーザーが言ったときだけ） |
| -------------------------------------- | ------------------ | ------------ | -------------------------------- |
| 取り消した確認をもう一度完了にできるか | できない。作り直す | 同じ         |                                  |
```
