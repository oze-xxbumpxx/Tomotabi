# ダッシュボードのデータの形

`decision-dashboard.mjs check`が確かめる。実例は[example.json](example.json)。

## 全体

| 項目       | 必須   | 中身                                                                     |
| ---------- | ------ | ------------------------------------------------------------------------ |
| `title`    | はい   | 左上の見出しとページ名。検討の名前（「本の登録画面の保存ボタン」）にする |
| `subtitle` | いいえ | 見出しの下の1行。今決めること                                            |
| `round`    | いいえ | 回。初回は1。続きを出し直すたびに1つ上げる（答えを回ごとに分けるため）   |
| `items`    | はい   | 問いと作業の並び。この順に番号（Q1, Q2, T1）が付く                       |

## 問い（`type: "question"`）

| 項目        | 必須                   | 中身                                                                                                                                                                                                      |
| ----------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`        | はい                   | 英小文字・数字・ハイフン。ページの答えと問いを結ぶ機械用の名前で、文章では使わない                                                                                                                        |
| `state`     | はい                   | `waiting`（今答えてほしい。10件以内）、`tentative`（推奨で仮に進め、異議を受ける）、`later`（後で決める。答える欄なし）、`decided`（決まった）                                                            |
| `label`     | はい                   | 問いの1文                                                                                                                                                                                                 |
| `kind`      | 回答待ちでは必須       | 画面 / アプリの決まり / API / 設計 / 実装 / 改善 / 不具合。色つきの札になる                                                                                                                               |
| `body`      | いいえ                 | 問いの背景。2〜3文                                                                                                                                                                                        |
| `facts`     | いいえ                 | 判断の材料。短い文の配列                                                                                                                                                                                  |
| `options`   | はい（決定済みは任意） | 選択肢。2つ以上。`key`（A, B, ...）、`title`、`pros`、`cons`が必須。`summary`（1文）、`mock`（見本のSVGかHTML）、`verify`（確かめ方）、`scope`（影響範囲）は任意。不具合の問いでは`verify`と`scope`を書く |
| `recommend` | 回答待ち・仮決定で必須 | 推奨の`key`                                                                                                                                                                                               |
| `reason`    | 回答待ち・仮決定で必須 | 推奨の理由。1文                                                                                                                                                                                           |
| `decision`  | 決定済みで必須         | `choice`（選んだ答え）、`reason`（ユーザーが言った理由）、`rejected`（選ばなかった理由）。理由は無ければ書かない                                                                                          |
| `panels`    | いいえ                 | 右の欄の図。`title`と、`figure`（SVGかHTML）か`body`（文）のどちらか                                                                                                                                      |
| `evidence`  | いいえ                 | 「見た実物」。確かめた事実の配列                                                                                                                                                                          |

## 作業（`type: "task"`）

ユーザーにしかできないこと（実機で見る、アカウントで操作する）。`id`・`state`・`label`のほかに、`body`か`steps`（手順の配列）が要る。
ページには「やった」のチェックとメモ欄が出る。`panels`と`evidence`は問いと同じ。

## 図（`figure`）と見本（`mock`）の書き方

- SVGを使う。`viewBox`を付け、幅と高さは書かない（欄の幅に合わせて縮む）。
- 色は、本文や線なら`currentColor`（明るい表示と暗い表示の両方で読める）、見せたい画面の色はその色そのまま。
- 文字は`font-size`を10〜12にする。図の中の文字が多いときは、図でなく文で書く。
- `script`・`iframe`・`on*`属性・`javascript:`は使えない。外のURLの画像も読めない。

## ページが保存する答え

ページのデータベースに、書きかけ（`drafts/<id>`）と、「答えを送る」で確定した写し（`submissions/r<round>`）を分けて置く。
読むのは写しだけ。`submissions/r<round>`の`answers`は、`id`ごとに次の形。

- 問い: `{no, label, choice, other, note, recommended}`。`choice`は選択肢の`key`か`"other"`（そのとき`other`に本文）
- 作業: `{no, done, note}`
