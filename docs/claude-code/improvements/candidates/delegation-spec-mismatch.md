## 観測した事象

### 事象 1: 設計書の表（エラーの扱い・状態の遷移・契約）の一部の行が実装に反映されない

- **種類**: レビュー指摘
- **観測した事象**:
  - #73（PR #74。API）: 作成の再送の確認が参加者の確認より後で、利用停止後に 409 になる（nit）。旅行名の変更の経路が契約と違う（must）。`DATABASE_URL` が空文字のとき起動しない（must）。
  - #76（PR #77。web の基盤）: 結果不明（unknown）から編集に戻ると新しいキーで保存し直せる（must。保存状態の遷移）。要求の本文が参照のまま保存され、確認の再送で本文が変わり得る（must）。
  - #80（PR #84。画面）: 書き込みの 403 / 404 で C-2 を出さず汎用文と再試行を出す（must）。表示後の再取得が 401 のとき業務データを隠さない（must）。0 件表示のときの再取得の失敗が出ない（nit）。
- **発生回数**: 異なる委譲で 3 件（#73・#76・#80）。いずれも L3。Claude Code のレビュー（#80 はサブエージェントの reviewer）で見つかり、マージ前に直った。
- **原因仮説**: 3 件とも、Issue は該当する設計書の節・表を「読む資料」に挙げていた（#80 は「エラー応答」の code 表と 07 §11 を名指し）。読ませること自体は足りている。
  外れたのは、表の**正常系以外の行**（403 / 404 / 401 の表示の出し分け、unknown からの遷移、空文字の環境変数）と、契約の経路のような**細部の 1 行**。
  Devin は表を読んで代表の行を実装し、残りの行を汎用の扱い（汎用文と再試行など）でまとめて完了とみなしている。
  PR の説明にも「どの行をどう実装したか」を書く欄が無く、抜けた行はレビューで表と突き合わせるまで見えない。
- **改善案**: `devin-workflow` §4 の PR の説明に、Issue が参照した設計書の表（エラーの code と表示・状態の遷移・契約の経路）の**行ごとの対応**（実装の場所とテスト）を書く項目を足す。
  書けない行は、実装せずに止まって報告するという既存の約束（Issue の「やらないこと」）につなげる。
  どの委譲にも効く予防なので `devin-workflow` に置き、`review-devin-pr` の「既知の指摘」の表には書かない。
- **別案と比べた理由**:
  - Issue に表の行を全部写す（Issue の書き方で直す）→ 設計書と Issue の二重管理になり、写し漏れが同じ問題を起こす。Issue は既に表を名指ししている。
  - `devin-workflow` §2 に「表のすべての行を実装する」と 1 行足すだけ → IMP-2026-002・003 と同じ「心がけ」の指示で、守られたかを外から確かめられない。
    PR の説明の対応表なら、抜けた行がレビューの最初の数分で見える（レビューの手間も減る）。
- **変更対象**: Skill（`.agents/skills/devin-workflow/SKILL.md` §4）
- **想定される副作用**: PR の説明が長くなる。L0 / L1 や、設計書の表を参照しない Issue では書かない（「参照した表があれば」に限った）。
- **評価方法**: 軽量サイクルの事後評価。昇格後の 3 委譲（L3 を含む）で `spec-mismatch` が 0 件ならよし（`delegation.mjs summary`）。
  あわせて、PR の説明に対応表があったか・抜けた行が対応表から見えたかを、レビューのときに記録（日次ログ）に残す。再発したらこのファイルに追記して見直す。
- **昇格判定**: 昇格条件を満たす（異なる Issue で 3 件）

## 変更差分

```diff
 ## 4. PR
 
 - タイトルは既存に合わせる（`feat:` / `fix:` / `docs:` + 日本語）。
 - 説明に「変更レベルと、ユーザー承認: 必要 / 不要」「何を・なぜそう設計したか・別の方法との比較」「実行した品質確認と結果」を書く。L1 の説明は 3 行以内の要約でよい。
+- Issue が設計書の表（エラーの code と表示・状態の遷移・契約の経路など）を参照していたら、説明に表の**行ごと**の対応（実装の場所・テスト）を書く。正常系以外の行（403 / 404 / 401、結果不明、空の入力など）を汎用の扱いでまとめない。対応を書けない行があれば、実装を変えずに止まって報告する。
 - マージはユーザーが行う。Devin はマージしない。
```
