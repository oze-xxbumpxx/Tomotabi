# 論点の記録: 初めて使った人のレビューで、直し方を決めるもの

- 機能名: first-use-decisions
- 確認のページ: https://claude.ai/artifact/ND7UXTBywDYeuntAxf3Wan
- 進み具合: docs/discussions/first-use-decisions.progress.json
- v3の版: 9db5634a

## 背景

初めて使った人のレビュー（#253）の9つの指摘のうち、直し方が決まっていた3つ（日付の書き方・切り替えの矢印とログアウトの区切り・通知の設定の戻るリンクと止める前の確認）は直してマージした（#292・#294・#295）。残りの7つは、どう直すかで画面の動きや見た目が変わるので、直す前に決めてもらう。この記録では、7つそれぞれの直し方を決める。決まったら、まとめて1つの設計にして直す。

## 前提

- 二人で使うアプリで、主に手元のスマートフォンで使う。パソコンの画面は、出発前に予定を入れるときなどに使う。
- 本文の幅は`main`の`max-width: 40rem`（`apps/web/src/app/globals.css:108`）。下のタブと浮かぶ主ボタンも同じ40remに合わせている（`globals.css:2233`・`:2290`）。
- 下の主ボタンは、指定が無ければ「支払いを記録」になる（`features/trips/ui/trip-tab-bar.tsx:100`）。精算の画面は指定していないので「支払いを記録」が浮かび、画面の中には精算の主な操作「受け渡しの内容を確かめる」がある（`screens/settlement/settlement-screen.tsx:286`・`:372`）。
- 旅行のメニュー（「…」）は、ホームとしおりから開く。ホームのヘッダーには「切り替え」もあるが、しおりのヘッダーには無い。
- 一番小さい文字は11pxで、10か所にある（`globals.css`の`.field-optional`・`.tabbar-item`・`.pay-share-sub`・`.settle-tile-label`・`.rrow-pill`など）。補足の文字は薄い色（`--color-text-muted`）。
- 履歴（記録一覧）では、取り消した支払いは線で消して「取り消し済み」を付け、別の行に「〇〇を取り消し」を出す。取り消しの行にも元の金額が出る（`features/records/ui/record-list.tsx:106`・`:115`）。
- 通知の設定への入口は、旅行のメニューの「この端末の通知」と、ホームの上の案内のカードの2つ。案内のカードは、この端末で通知が有効でなく、閉じていないときだけ出る（`features/notifications/ui/notification-guide-card.tsx`）。
- 人の名前は表示名で出す。自分も相手も名前だけで、どちらが相手かの印は無い（`features/trips/model/home-model.ts:117`）。

## 論点

### 広い画面で、本文の幅をどうするか

<!-- id: wide-screen-width -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 03, v3 08
- なぜ今: 幅を変えるなら、本文・下のタブ・主ボタン・下からの小さな画面の4つを同じ値でそろえる必要があり、どこまで変えるかで直す範囲が決まる。
- 根拠: #253「パソコンで見ると、真ん中の狭い列に内容が寄る」。今は40rem（640px）。v3はスマートフォンの幅で描かれていて、広い画面の見本は無い。
- 選択肢:
  - A) 今の40remのまま
    - 利点: 何も変えずに済み、スマートフォンで見たときと同じ並びになる
    - 欠点: パソコンでは左右の余白が大きく、狭い列に寄って見えるまま
  - B) 横幅が1024px以上の画面だけ、4つをそろえて48rem（768px）に広げる
    - 利点: 1段の並びは変えずに、パソコンで読みやすい幅になる
    - 欠点: 行が横に長くなり、金額や時刻が名前から離れて見える行が出る
  - C) 広い画面では2段に分ける（例: ホームの予定と精算を横に並べる）
    - 利点: パソコンの広さを使い切れる
    - 欠点: 画面ごとに並べ方を新しく決める必要があり、v3に無い見た目を多く作ることになる
- 推奨: B（作りを変えずに幅だけを広げられ、主に使うスマートフォンの見た目は変わらない）

### 精算の画面で、浮かぶ「支払いを記録」をどうするか

<!-- id: settlement-main-action -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 14, v3 14b
- なぜ今: 主ボタンを消すか、弱く見せるかで、下のタブの部品に足す指定が変わる。
- 根拠: #253「精算を見ているときにも、支払いを記録が浮かんでいる」。精算の画面には「受け渡しの内容を確かめる」があり、主な操作が2つ並んで見える。
- 選択肢:
  - A) 精算の画面では出さない。支払いを記録するときは、ホーム・しおり・履歴から押す
    - 利点: 精算の画面の主な操作が「受け渡しの内容を確かめる」の1つになる
    - 欠点: 精算を見ていて記録し忘れに気づいたとき、ほかのタブへ1回移る手間が増える
  - B) 出すが、枠だけの小さなボタンにして、この画面では脇の操作だと分かる見た目にする
    - 利点: 精算からすぐに記録でき、主な操作とも見分けられる
    - 欠点: 主ボタンの見た目が画面で変わり、下のタブの部品に新しい見た目を1つ足す
  - C) 今のまま
    - 利点: どの画面でも同じ場所から記録できる
    - 欠点: 主な操作が2つ並んで見えるまま
- 推奨: A（精算の画面でやることは受け渡しの確認なので、主な操作を1つにしたほうが迷わない。記録し忘れは、ほかのタブから1回で開ける）

### 旅行の切り替えの入口を、メニューとホームのヘッダーの両方に残すか

<!-- id: switch-entry -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 03, v3 16, v3 08
- なぜ今: 片方を消すと、入口が無くなる画面が出るので、代わりの入口も一緒に決める必要がある。
- 根拠: #253「…メニューの旅行を切り替えは、ヘッダーの切り替えと重なる」。しおりのヘッダーには切り替えが無く、しおりではメニューが唯一の入口になる。矢印とアイコンは#295で直し、ドロップダウンには見えなくなった。
- 選択肢:
  - A) 両方残す
    - 利点: どの画面からでも切り替えられ、何も消さずに済む
    - 欠点: ホームでは同じ入口が2つあるまま
  - B) メニューから消し、しおりのヘッダーにも「切り替え」を足す
    - 利点: 入口がヘッダーの1つにそろい、メニューが短くなる
    - 欠点: しおりのヘッダーに要素が1つ増え、v3の08から外れる
  - C) ホームのヘッダーから消し、メニューだけにする
    - 利点: 入口がメニューの1つにそろう
    - 欠点: ホームから切り替えるのに1回多く押す。v3の03から外れる
- 推奨: A（矢印を直したことで、重なりの分かりにくさは減った。しおりで入口が無くならず、v3からも外れない）

### 小さい補足の文字の大きさと濃さをどうするか

<!-- id: small-text -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 11, v3 14, v3 10
- なぜ今: どの文字を変えるかで、直す箇所の数と、行の高さが変わる画面が決まる。
- 根拠: #253「補足の一部がおおよそ10pxで、コントラストが低い」。今の一番小さい文字は11pxで10か所。補足は薄い色。
- 選択肢:
  - A) 補足の文字（「任意」・負担の補足・精算の小見出し・取り消し済みの印など）を12pxにし、色を一段濃くする。下のタブの名前は11pxのまま
    - 利点: 読みにくいと言われた補足が読みやすくなり、下のタブの並びは変わらない
    - 欠点: 行の高さが少し増え、精算の小見出しのように詰めて並べた所で折り返しが出るかもしれない
  - B) 11pxの文字をすべて12px以上にし、色も濃くする（下のタブの名前も含む）
    - 利点: 一番小さい文字が無くなり、決まりが分かりやすい
    - 欠点: 下のタブの4つの名前が狭い画面で窮屈になる
  - C) 大きさは変えず、色だけ濃くする
    - 利点: 並びが変わらない
    - 欠点: 大きさの読みにくさは残る
- 推奨: A（読みにくいのは補足の文字で、下のタブの名前は短いのでスマートフォンのいつもの大きさのままでよい）

### 履歴で、取り消した支払いと取り消しの記録をどう並べるか

<!-- id: cancelled-payment-rows -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 10, v3 12
- なぜ今: 取り消しの行を残すか消すかで、履歴の絞り込みと、取り消しを誰がいつしたかの出し方が変わる。
- 根拠: #253「取り消し済みの行と、支払いを取り消した記録が並ぶと、支払いが二件あるように見える」。取り消しの行にも元の金額が出ている（`record-list.tsx:115`）。
- 選択肢:
  - A) 2行のまま残し、取り消しの行から金額を外して「精算から外しました」と書く
    - 利点: 誰がいつ取り消したかが今までどおり1行で分かり、金額が2回出なくなる
    - 欠点: 行の数は2つのまま
  - B) 取り消しの行を一覧から外し、元の行に「取り消し済み · 〇〇が10/13に取り消し」とまとめる
    - 利点: 1つの支払いが1行になる
    - 欠点: 取り消した日の見出しの下には何も出なくなり、その日に何をしたかを追いにくい
  - C) 今のまま
    - 利点: 何も変えない
    - 欠点: 支払いが2件あるように見えるまま
- 推奨: A（二人のどちらが何をしたかを日ごとに追えるまま、金額が2回出る分かりにくさだけを直せる）

### 通知の設定への入口を、メニューのほかにも置くか

<!-- id: notify-entry -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 16, v3 03
- なぜ今: 入口を足すなら、どの画面のどこに置くかで直す画面が決まる。
- 根拠: #253「通知設定は旅行メニューの奥にあり、見つけにくい」。今の入口はメニューと、ホームの案内のカード（通知が有効でなく、閉じていないときだけ）。
- 選択肢:
  - A) 今のまま（メニューと案内のカード）
    - 利点: 何も足さずに済む。通知を有効にする前は案内のカードから入れる
    - 欠点: 案内のカードを閉じたあとや、有効にしたあとは、メニューの奥からしか入れない
  - B) 旅行の一覧の画面の上に、通知の設定へのリンクを足す
    - 利点: 旅行に入らずに設定を開け、旅行ごとの設定ではないことも伝わる
    - 欠点: 旅行の一覧に要素が1つ増える
  - C) ホームのヘッダーに鈴のアイコンを足す
    - 利点: 旅行中にいつでも1回で開ける
    - 欠点: ヘッダーが混み、鈴は「お知らせの一覧」と思われやすい
- 推奨: B（通知の設定は旅行ではなく端末の設定なので、旅行の一覧に置くと意味が合い、ヘッダーも混まない）

### 相手の名前のそばに「相手」と付けるか

<!-- id: partner-label -->

- 工程: 設計
- 種類: 画面
- 優先度: 高
- 状態: 回答待ち
- 画面: v3 14, v3 03, v3 10
- なぜ今: 付ける場所の範囲で、直す画面の数と、名前を出す部品の作りが変わる。
- 根拠: #253「相手の名前だけが出て、それが相手（もう一人）だと分からない」。名前は自分も相手も表示名だけで出る（`home-model.ts:117`）。
- 選択肢:
  - A) 精算・ホームの精算のカード・支払いの詳細のように、二人の名前が並ぶ所だけ、相手の名前の後ろに小さく「（相手）」と付ける
    - 利点: 誰から誰へ渡すかが一目で分かり、直す所が少ない
    - 欠点: 履歴の行のように名前が1つだけの所は、今のまま
  - B) 名前を出すすべての所で、相手の名前に「（相手）」を付ける
    - 利点: どこを見ても同じ決まりになる
    - 欠点: 履歴の行が長くなり、折り返しが増える
  - C) 自分の名前を「あなた」と出し、相手は名前のまま
    - 利点: 印を足さずに、どちらが自分かが分かる
    - 欠点: 通知や履歴など、名前を出す言葉を全部見直すことになる
- 推奨: A（取り違えると困るのはお金の受け渡しの向きなので、二人の名前が並ぶ所に絞ると、直す所が少なく効き目も大きい）
