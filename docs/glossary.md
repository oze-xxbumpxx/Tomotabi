# 用語集

ユーザーへの説明（チャット・PRの説明・報告）で使うプロジェクトの用語。正本（基本設計・詳細設計・`docs/design/handoff-v3/`）の言葉を優先し、正本に無い言葉は説明のために足したもの（「足した」と書く）。番号（段階・画面・試験の観点）だけで物事を指さず、ここの言葉で書く（AGENTS.md）。

用語を足すときは、この表に1行足す。言い換えが要る言葉を見つけたら、その場で足してよい。

## 開発の段階

詳細設計10「実装順序」の段階。会話では番号（M0など）でなく名前で呼ぶ。

| 名前 | 番号 | 中身 |
| --- | --- | --- |
| 開発基盤 | M0 | monorepo・Next.js・NestJS・CIの骨組み |
| DB・認証 | M1 | DBの表とmigration、Googleログイン、二人の登録 |
| 旅行・予定 | M2 | 旅行の作成・選択・開始・終了、しおりと予定 |
| E2Eの土台 | （足した） | 旅行・予定のあとに入れた、ブラウザでの自動の試験（Playwright）とCI |

| 記録と4画面の完成 | M4 | 達成・予約の記録、記録一覧、ホーム、精算の例外の画面 |
| 通知 | M5 | プッシュ通知 |
| 結合検証環境 | M6 | Vercel・Neonで本番に近い環境を作って確かめる |

| 初回公開 | M8 | 公開と運用の記録 |

## 業務の言葉

| 用語 | 意味 | 出典 |
| --- | --- | --- |
| しおり | 旅行の日ごとの予定の一覧 | 詳細設計05・v3 |
| 取りやめ | 予定をやめること（予定は残り、取りやめの印が付く） | 詳細設計04 |
| 取り消し | 支払い・精算・達成・予約の記録を打ち消すこと（元の記録は残り、取り消しの記録を足す） | 詳細設計01・04 |
| 精算 | 二人の間の立て替えを清算すること。アプリは送金しない | 詳細設計01 |
| 受け渡し | 精算で実際にお金を渡すこと（アプリの外で行う） | 詳細設計01・v3 |
| 受け渡しの確認 | 精算する対象と金額を、作った時点で固定したもの。あとから支払いが増えても変わらない | 詳細設計01（settlement preview） |
| 精算の対象 | まだ精算していない支払い（と、精算後に取り消された支払いの戻し） | 詳細設計01 §4 |
| 結果不明 | 保存を送ったが、通信が切れるなどで保存されたか分からない状態 | 詳細設計07 §9 |
| 同じ要求で確かめる | 結果不明のとき、同じ内容・同じキーで送り直して結果を確かめること。二重に保存されない | 詳細設計07 §9 |
| 競合 | 相手が先に同じものを変えていて、保存できないこと。違いを見比べてから保存し直す | 詳細設計07 §10 |
