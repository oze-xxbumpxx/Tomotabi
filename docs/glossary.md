# 用語集

ユーザーへの説明（チャット・PR の説明・報告）で使うプロジェクトの用語。正本（基本設計・詳細設計・`docs/design/handoff-v3/`）の言葉を優先し、正本に無い言葉は説明のために足したもの（「足した」と書く）。番号（段階・画面・試験の観点）だけで物事を指さず、ここの言葉で書く（AGENTS.md）。

用語を足すときは、この表に 1 行足す。言い換えが要る言葉を見つけたら、その場で足してよい。

## 開発の段階

詳細設計 10「実装順序」の段階。会話では番号（M0 など）でなく名前で呼ぶ。

| 名前 | 番号 | 中身 |
| --- | --- | --- |
| 開発基盤 | M0 | monorepo・Next.js・NestJS・CI の骨組み |
| DB・認証 | M1 | DB の表と migration、Google ログイン、二人の登録 |
| 旅行・予定 | M2 | 旅行の作成・選択・開始・終了、しおりと予定 |
| E2E の土台 | （足した） | 旅行・予定のあとに入れた、ブラウザでの自動の試験（Playwright）と CI |
| 支払い・精算の中核 | M3 | 支払いの記録、残額の計算、精算の確認・完了・取り消し |
| 記録と 4 画面の完成 | M4 | 達成・予約の記録、記録一覧、ホーム、精算の例外の画面 |
| 通知 | M5 | プッシュ通知 |
| 結合検証環境 | M6 | Vercel・Neon で本番に近い環境を作って確かめる |
| 公開準備 | M7 | 本番の設定・初期登録・バックアップの手順 |
| 初回公開 | M8 | 公開と運用の記録 |

## 業務の言葉

| 用語 | 意味 | 出典 |
| --- | --- | --- |
| しおり | 旅行の日ごとの予定の一覧 | 詳細設計 05・v3 |
| 取りやめ | 予定をやめること（予定は残り、取りやめの印が付く） | 詳細設計 04 |
| 取り消し | 支払い・精算・達成・予約の記録を打ち消すこと（元の記録は残り、取り消しの記録を足す） | 詳細設計 01・04 |
| 精算 | 二人の間の立て替えを清算すること。アプリは送金しない | 詳細設計 01 |
| 受け渡し | 精算で実際にお金を渡すこと（アプリの外で行う） | 詳細設計 01・v3 |
| 受け渡しの確認 | 精算する対象と金額を、作った時点で固定したもの。あとから支払いが増えても変わらない | 詳細設計 01（settlement preview） |
| 精算の対象 | まだ精算していない支払い（と、精算後に取り消された支払いの戻し） | 詳細設計 01 §4 |
| 結果不明 | 保存を送ったが、通信が切れるなどで保存されたか分からない状態 | 詳細設計 07 §9 |
| 同じ要求で確かめる | 結果不明のとき、同じ内容・同じキーで送り直して結果を確かめること。二重に保存されない | 詳細設計 07 §9 |
| 競合 | 相手が先に同じものを変えていて、保存できないこと。違いを見比べてから保存し直す | 詳細設計 07 §10 |
| 参加者番号 | 旅行の二人に振る固定の番号 0 と 1（DB の slot）。ログインを許可した順で 0 がひなた、1 があおい。金額の向きの基準 | 詳細設計 01（足した呼び名） |
| 寄与 | 支払い 1 件が二人の貸し借りに与える量。参加者番号 1 の人から 0 の人へ渡す向きを正にした符号付きの円 | 詳細設計 01 |
| 占有 | どの支払いが、どの精算で済んでいるかの今の状態の記録（active_claims） | 詳細設計 01（足した呼び名） |
| 戻し | 精算済みの支払いがあとで取り消されたときに、次の精算で打ち消す明細（REVERSAL） | 詳細設計 01（足した呼び名） |
| 指紋 | 受け渡しの確認を作った時点の、支払いの精算と取り消しの履歴をまとめた短い値。完了のときに比べて対象の変化を見分ける | 詳細設計 01（fingerprint） |
| 受領 | 同じ要求の再送を見分けるための保存の記録（command_receipts） | 詳細設計 01 |
| 財務の順番待ちの札 | 旅行ごとに 1 行ある guard の行。お金の書き込みは最初にこれをロックして一列に並ぶ | 詳細設計 01（足した呼び名） |
