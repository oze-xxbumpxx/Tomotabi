# 実装計画: first-use-polish（初めて使った人のレビューの細かい点を直す）

- 関連: #253（広い画面・共通ボタン・メニュー・日付・取り消し表示・通知の見つけにくさ）
- レベル: L1（直し方が#253に書いてあり、決めることが無いものだけ）

## この計画で直すもの

#253の9つの指摘のうち、直し方が決まっていて画面の動きを大きく変えない3つを、Devinに1つずつ渡す。手元のDevinは専用クローンを1つしか使わないので、3つは順に進める。

| タスク | 何を直すか |
| --- | --- |
| `date-format` | 日付を`11/1(日)`の形にそろえる |
| `switch-and-logout` | 旅行の切り替えの矢印を右向きにし、メニューのログアウトを他の項目から離す |
| `notify-back-and-stop` | 通知の設定の戻るリンクに行き先の名前を出し、この端末の通知を止める前に確認を出す |

## この計画で直さないもの

次の7つは、どう直すかを決める必要があるので、問いにしてユーザーに出す。決まったら別の計画にする。

- 広い画面での本文の幅
- 精算の画面に浮かぶ「支払いを記録」
- メニューの「旅行を切り替え」とホームのヘッダーの「切り替え」の重なり（しおりの画面にはヘッダーの切り替えが無いので、片方を消すと入口が無くなる画面がある）
- 小さい補足の文字の大きさと濃さ（今の一番小さい文字は11px）
- 取り消し済みの支払いと、支払いを取り消した記録の並び方
- 通知の設定への入口を、メニューの奥のほかにも置くか
- 相手の名前のそばに「相手」と付けるか

<!-- delegation-task:date-format -->
## 目的

日付の書き方を`11/1 日`から`11/1(日)`に変え、曜日が日から離れて見えないようにする（#253）。L1、ユーザー承認: 不要。

## 読む資料

- `apps/web/src/shared/lib/local-date.ts`の`formatLocalDate`と`formatTripPeriod`
- `formatLocalDate`・`formatTripPeriod`を使っている画面（`grep -rn "formatLocalDate\|formatTripPeriod" apps/web/src`）

## やること

- [ ] `formatLocalDate`が`11/1(日)`の形（月/日、すぐ後ろに半角かっこで曜日）を返すようにする。
- [ ] `formatTripPeriod`は`10/12(月) – 10/14(水)`の形になる（区切りの` – `は今のまま）。1日だけの旅行は1つだけ出す今の動きを保つ。
- [ ] 2つの関数のJSDocの例を新しい形に直す。
- [ ] 画面の上の日付の文字列を探している単体の試験とE2Eを、新しい形に直す。

## テスト

- [ ] `formatLocalDate`と`formatTripPeriod`の単体の試験で、新しい形と、1日だけの旅行の形を確かめる。
- [ ] `npm test`と`npm run test:e2e`が通る。

## 既知の指摘（関係する領域のときだけ）

- E2E: 日付は今日から数えて作り、年や日を決め打ちしない。要素は役割・見出し・ラベルで探し、クラス名で探さない。APIを模擬したら、外す条件をPRの説明に書く。

## やらないこと

- `formatLocalDate`を使っていない日付の書き方（時刻だけ、`10月12日`のような文）は変えない。
- 日付の計算（期間の日の並び、今日の判定）は変えない。

## 完了条件

- `npm run lint` / `npm run type-check` / `npm test` / `npm run build`が通る。
- 旅行の一覧・ホーム・しおり・予定の詳細で、日付が`11/1(日)`の形で出る。

<!-- delegation-task:switch-and-logout -->
## 目的

旅行の切り替えがドロップダウンに見えて別のページを開く点と、メニューのログアウトが他の項目と並んでいる点を直す（#253）。L1、ユーザー承認: 不要。

## 読む資料

- `apps/web/src/screens/home/home-header.tsx`（ホームのヘッダーの「切り替え」）
- `apps/web/src/features/trips/ui/trip-menu.tsx`（「…」のメニュー）
- `apps/web/src/app/globals.css`の`.menu-item`まわり

## やること

- [ ] ホームのヘッダーの「切り替え」の下向きの矢印（`CaretDown`）を、右向きの矢印（`CaretRight`）にする。押すと旅行の一覧を開く動きは変えない。
- [ ] メニューの「旅行を切り替え」の左のアイコンを、下向きの矢印から、ドロップダウンに見えないもの（例: `ArrowsClockwise`）にする。右端の`CaretRight`は今のまま。
- [ ] メニューの「ログアウト」の上に区切り線か余白を入れ、他の項目から離す。ログアウトの文字の色と、押したときの動きは変えない。

## テスト

- [ ] ヘッダーの「切り替え」が旅行の一覧へのリンクのまま、下向きの矢印を使っていないことを確かめる単体の試験。
- [ ] メニューの項目の並び（旅行を切り替え・この端末の通知・ログアウト）が変わっていないことを確かめる単体の試験。

## やらないこと

- メニューから「旅行を切り替え」を消さない（しおりの画面にはヘッダーの切り替えが無いため）。
- メニューの項目を足したり、並びを変えたりしない。

## 完了条件

- `npm run lint` / `npm run type-check` / `npm test` / `npm run build`が通る。

<!-- delegation-task:notify-back-and-stop -->
## 目的

通知の設定の画面で、戻るリンクが矢印だけで行き先がわからない点と、この端末の通知を確認なしで止められる点を直す（#253）。L1、ユーザー承認: 不要。

## 読む資料

- `apps/web/src/screens/notification-settings/notification-settings-screen.tsx`（`backHref`と「この端末の通知を止める」）
- 確認のダイアログの例: `apps/web/src/features/plans/ui/cancel-plan-dialog.tsx`と`apps/web/src/shared/ui/dialog.tsx`

## やること

- [ ] 戻るリンクに、矢印と一緒に行き先の名前を出す。`backHref`が旅行のホームなら「ホーム」、旅行の一覧なら「旅行一覧」にする。見た目は予定の詳細の「← しおり」と同じ`plan-back`の形にそろえる。`aria-label="戻る"`は外し、見えている文字を読み上げの名前にする。
- [ ] 「この端末の通知を止める」を押したら、`Dialog`で確認を出す。見出しは「この端末の通知を止めますか？」、本文は「止めると、この端末には通知が届かなくなります。あとからこの画面でもう一度登録できます。」、ボタンは「やめる」と「止める」。「止める」で今の止める処理を呼ぶ。

## テスト

- [ ] 戻るリンクの名前が、行き先に合わせて「ホーム」か「旅行一覧」になる。
- [ ] 「この端末の通知を止める」で確認が開き、「やめる」なら止める要求を送らない。「止める」で今までどおり止まる。

## やらないこと

- ほかの端末の行の「止める」には確認を足さない。
- 通知の設定への入口（メニューの項目）は変えない。

## 完了条件

- `npm run lint` / `npm run type-check` / `npm test` / `npm run build`が通る。
