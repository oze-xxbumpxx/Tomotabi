# 公開の記録

本番に出すたびに、このフォルダに`YYYY-MM-DD.md`（同じ日に2回なら`YYYY-MM-DD-2.md`）を1つ足す。手順は[本番の手順書](../runbooks/production.md)の10章。秘密情報の値、dumpの中身、二人の個人の情報は書かない。

テンプレートは設計資料「運用設定と公開チェック」4節を元にした。

```markdown
# 公開の記録: YYYY-MM-DD

- 公開した日時:
- 対象のcommit（40桁）とCIの実行:
- 先に確かめた検証用のデプロイ（ActionsのURLと確かめた日）:
- 本番のデプロイ（ActionsのURL、webとapiのURL）:
- DB（Neonのプロジェクト・ブランチ、適用したmigrationの最後の番号。変えなければ「変更なし」）:
- 変更の前のバックアップと照合（ファイル名と照合の結果。DBを変えなければ「対象外」）:
- 設定の変更（変えた環境変数の名前だけ。値は書かない）:
- 公開のあとの確かめ（二人のログイン、ホームの表示、そのほか）:
- 前の版に戻すときのcommitと、DBとの互換:
- 書いた人:
```

最初の公開の記録には、要件の「確かめること（P-12）」の表（OPS-01〜18、OPS-09を除く）を足し、項目ごとに日付と結果を書く。
