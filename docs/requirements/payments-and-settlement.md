## この文書の読み方

- **F-01 などの番号**は、この要件定義の機能要件の番号。**E-01 など**は異常系（うまくいかない場面）の番号。設計書・試験計画から「どの要件を満たすか」を指すために付けている。
- **参加者番号**は、旅行の二人に振る固定の番号 0 と 1（DB では slot）。ログインを許可した順で、0 がひなた、1 があおい。金額の向き（どちらからどちらへ）の基準に使い、画面では「自分」「相手」に直して見せる。
- **寄与**は、支払い 1 件が二人の貸し借りに与える量。参加者番号 1 の人から 0 の人へ渡す向きを正にした、符号付きの円。
- **guard の行**（`infra.trip_finance_guards`）は、旅行ごとに 1 行ある「お金の書き込みの順番待ちの札」。お金の書き込みは最初にこの行をロックするので、同じ旅行の書き込みは一列に並ぶ。精算の連番もここで払い出す。
- **占有**（`settlement.active_claims`）は、「どの支払いが、どの精算で済んでいるか」の今の状態の記録。同じ支払いを二つの精算に入れないために使う。
- **BASE と REVERSAL** は精算の明細の種類。BASE は支払いをそのまま精算すること（寄与 c）。REVERSAL は、精算済みの支払いがあとで取り消されたときの戻し（−c）。
- **指紋**は、受け渡しの確認を作った時点の、その支払いの精算と取り消しの履歴をまとめた短い値（sha256）。完了のときに作り直して比べ、違えば「対象が変わった」と分かる（金額が同じでも見分けられる）。
- **受領**（`infra.command_receipts`）は、同じ要求の再送を見分けるための保存の記録。同じキーで送り直すと、ここから元の結果を返す。

## 背景

旅行・予定の段階で、旅行と参加者二人（参加者番号 0・1）、旅行ごとの財務の guard（`infra.trip_finance_guards`）、再送の受領（`infra.command_receipts`）、書き込みの共通の流れ（ETag・Idempotency-Key・旅行単位のロック・保存状態）ができた。E2E の土台で、web と API をつないだ振る舞いをブラウザで自動に確かめられるようになった。

このアプリの中心は、二人の立て替えを記録して精算することにある。お金の記録は、二重にできたり、計算がずれたり、取り消しで消えたりしてはいけない。詳細設計「実装順序」は「金銭記録の整合性が UI の土台になる」ため、この段階を先に十分確かめるとしている。

## 目的

- 二人が支払いを記録し、残額（誰から誰へいくら）を見て、受け渡しの確認を作り、受け渡しの完了を記録できる。支払いと精算は取り消せる。
- 金額の計算（端数・符号・合計）、確認の固定、同時の操作、応答が消えたあとの再送、途中の失敗での巻き戻しを、実 DB と自動の試験で確かめる。
- 保存の結果が分からなくなったとき、画面を再読み込みしても同じ要求で確かめられるようにする（支払いと精算の保存から）。

## ユーザー要求（原文の要約）

「支払い・精算の中核に進みましょう」。2026-10-02 の確認で次を決めた。

- 画面の範囲: お金の計算と保存の仕組み（API と DB）は全部作る。画面はふつうの流れだけ作る（支払いを記録、精算、受け渡しの確認、対象が無いとき・0 円のとき）。確認のあとに支払いが取り消された・追加されたときの例外の画面、記録一覧、支払いを取り消す確認は、次の「記録と 4 画面の完成」に回す。
- 結果不明からの復帰: 再読み込みしても忘れないよう IndexedDB に残す。最初は支払いと精算の保存だけを対象にする。

- 試験: お金の計算と保存の大事な点はすべて自動の試験で確かめる。今回作る画面の流れは E2E にも足す。

## 機能要件

### 支払い

| ID | 要件 |
| --- | --- |
| F-01 | 参加者は、金額・払った人・負担の分け方・用途（任意）・関連する予定（任意）で支払いを記録できる |
| F-02 | 金額は 1〜9,999,999 円の整数。API では 10 進の整数文字列で受け渡す |
| F-03 | 負担の分け方は、参加者番号 0 の人の負担の割合（0〜100 の整数。もう一人は 100 から引いた値）で表す。折半・払った人が全額・もう一人が全額・割合を指定は、画面がこの割合に変換する |
| F-04 | 負担額: 払った人でない人の負担 = floor(金額 × その人の割合 ÷ 100)、払った人の負担 = 金額 − もう一人の負担。二人の割合と負担額を保存する |
| F-05 | 支払いの寄与 c（参加者番号 1 の人から 0 の人へ渡す向きを正）を保存する。払った人が参加者番号 0 なら c = 1 の人の負担、払った人が 1 なら c = −（0 の人の負担） |
| F-06 | 支払いを取り消せる（取り消しの記録を足す。元の支払いは残る）。取り消し済みの取り消しは既存の取り消しを返す |
| F-07 | 関連する予定は同じ旅行の予定に限る（取りやめた予定も選べる） |
| F-08 | 支払いを 1 件取得できる（取り消し状態を含む） |

### 残額と精算の対象

| ID | 要件 |
| --- | --- |
| F-10 | 残額（向き・金額・対象の件数・明細）を取得できる。保存済みの支払い・精算・取り消しから導出し、通知や非同期の処理に頼らない |
| F-11 | 対象の導出は詳細設計「支払いと精算」の「次回対象の導出」の表どおり（有効な支払いで精算前 → 戻しでない対象 c。取り消し済みで精算済み → 戻し −c。それ以外は対象なし） |
| F-12 | 対象 0 件と、対象ありで合計 0 円を区別する |
| F-13 | 不正な状態（戻しだけが有効、有効な支払いに戻しがある）を検出する |

### 受け渡しの確認

| ID | 要件 |
| --- | --- |
| F-20 | ボタン操作で、その時点の対象をすべて固定した確認を作れる。対象 0 件なら作れない |
| F-21 | 確認の明細・金額は、あとから支払いが増えても、画面の再取得でも変わらない |
| F-22 | 自分の未完了の確認を新しい順に一覧できる。自動で選ばない |
| F-23 | 確認を 1 件取得すると、元の明細と、現在の検証結果（そのまま完了できる・取り消された対象の了承が要る・対象が変わった・完了済み・完了後に取り消された）を返す |
| F-24 | 確認は自動で期限切れにしない |

### 精算

| ID | 要件 |
| --- | --- |
| F-30 | 確認を指定して受け渡しの完了を記録できる。非 0 円は「受け渡しを完了した」、0 円は「受け渡し不要」として記録する |
| F-31 | 完了時に対象が確認のときと変わっていたら拒否する（金額が同じでも、精算・取り消しの履歴が変わっていれば変わったとみなす） |
| F-32 | 確認のあとに対象の支払いだけが取り消され、利用者が変更を了承し全額を受け渡した場合は、例外として元の確認で記録できる（API は今回作る。了承の画面は次の段階） |
| F-33 | 1 つの確認の完了は 1 回だけ。旅行の中の精算に連番を振る |
| F-34 | 精算を取り消せる。取り消せるのは最新の有効な精算だけ。取り消し済みの取り消しは既存を返す |
| F-35 | 精算の履歴を一覧・取得できる（各件の取り消し状態と、取り消せるか） |

## 非機能要件（性能・セキュリティ・可用性など）

- 金額の計算は Node.js の BigInt と DB の bigint で行い、Number に通さない（9,999,999 円は Number でも正確だが、合計・符号付きの計算で丸めを持ち込まない）。
- 財務の書き込みは旅行単位で直列化する。ロック待ちは短い有限の時間で打ち切り、一時エラー（503・再試行可）にする。DB のロック中に通知・外部呼び出し・利用者の操作を待たない。
- 読み取り（残額・確認の検証）は 1 つのスナップショットから組み立てる（複数のクエリで違う時点を混ぜない）。
- 他人の旅行の支払い・確認・精算は読めず、書けない。旅行が無い・参加していないは 403、参加している旅行の中で対象が無いは 404（旅行・予定の段階と同じ使い分け）。
- 受領（receipt）は自動で消さない。
- エラーの応答とログに、金額の明細・用途・SQL・例外の中身を出さない。

## 正常系

1. ひなたが 7,001 円を折半で記録 → ひなたの負担 3,501 円、あおいの負担 3,500 円、寄与は払った人に応じた符号。
2. 支払いが 2 件ある旅行で残額を開く → 「あおい から → ひなた へ ○ 円」と件数・内訳。
3. 「受け渡しを確認する」→ 確認ができ、固定した金額の画面へ。そのあと 3 件目の支払いを記録しても、確認の金額は変わらない。
4. 確認の画面で「表示の全額を受け渡しました」をチェック →「受け渡し完了を記録」→ ダイアログで「記録する」→ 精算ができ、残額は 3 件目だけになる。
5. 合計 0 円の対象（例: 互いに同額を立て替え）→ 「受け渡しは不要です」→ 0 円の確認 →「受け渡し不要として精算を記録」。
6. 最新の精算を取り消す → 対象が元に戻り、再び精算できる。
7. 精算後に支払いを取り消す → その支払いの戻し（−c）が次の対象になる。

## 境界条件（null・空・上限/下限・権限境界）

- 金額 1 円・9,999,999 円は受け付け、0 円・10,000,000 円は拒否する。
- 割合 0 と 100（一人が全額）。1,001 円の折半（端数 1 円は払った人が負担）。
- 対象 0 件と、対象ありの 0 円。
- 用途は前後の空白を除いて 1〜100 文字（コードポイント）、空なら無し。
- 旅行の状態（出発前・旅行中・終了）に関係なく、支払いと精算はできる（終了後も精算できる。v3 の終了の確認の文言どおり）。
