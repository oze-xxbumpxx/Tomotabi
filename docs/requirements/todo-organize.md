- 作成日: 2026-11-14
- ステータス: approved（PR #350）
- 決めたこと: `docs/discussions/todo-organize.md`（確認のページ: https://claude.ai/artifact/RkrTGDx64nX4sjzjk8zJAT ）
- 画面の見本: https://claude.ai/artifact/LRsVh7g3KmuPN4bfVNtXrE （2026-11-14にユーザーが採用。v3の画面一式にToDoの画面は無い）
- 元の要件: `docs/requirements/trip-todo.md`（この文書は、その上に足すものと変えるものだけを書く）

## この文書の読み方

- **F-01などの番号**は機能要件、**E-01など**は異常系、**B-01など**は境界の番号。この文書の中の番号で、`trip-todo`の番号を指すときは「元のF-12」と書く。
- **カテゴリ**は、二人が名前を付けて作る、ToDoを分ける欄。
- **関連付け**は、ToDoとしおりの予定1つを結ぶこと。ToDoの完了とは別に持つ。

## 背景

ToDoを項目ごとに分け、予定に関連付けたい、とユーザーから要望があった（2026-11-14）。今のToDoは名前とメモだけを持ち、1つのリストに追加した順で並ぶ。予定と結べるのは「予定にする」で完了にしたときだけで、「切符を買う」のような、予定の前に済ませる用事を予定と結べない。

## 目的

- 二人が、ToDoを自分たちのカテゴリに分けて見られる。
- どちらがいつまでにやるかを、ToDoに書ける。
- 未完了のToDoを予定と結び、予定の詳細で「この予定までにやること」の残りを確かめられる。

## ユーザー要求（原文の要約）

「ToDo機能で、項目ごとに分けたり、予定に関連付けしたりしたいです」「少し機能的にはリッチにしたい」。画面の見本と言葉を2026-11-14に採用し、同じ日に確認のページで6つを決めた（理由と選ばなかった案は論点の記録）。

- 完了の印を外しても、予定との関連付けは残す。
- ToDoから予定を作っても、ToDoは完了にしない。作った予定と関連付けるだけにする。
- カテゴリを削除すると、中のToDoも一緒に削除する（推奨は「未分類に移す」だった）。
- カテゴリは最初から用意しない。カテゴリの無いToDoは「未分類」に出す。
- カテゴリは並べ替えられる。ToDoは並べ替えない。
- 期限が近づいても通知は送らない。画面の印だけにする。

## 機能要件

### カテゴリ

| ID   | 要件                                                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-01 | カテゴリは旅行ごとに持つ。旅行の参加者（二人）だけが見て、追加・名前の変更・並べ替え・削除ができる                                                    |
| F-02 | ToDoは、カテゴリ1つに入るか、どれにも入らない（未分類）。あとから別のカテゴリに移せ、未分類にも戻せる                                                 |
| F-03 | リストはカテゴリごとの欄に分けて出す。欄の中は未完了を上、完了を下にし、それぞれ追加した順に並べる。元の「まだのもの」「済んだもの」の2つの欄はやめる |
| F-04 | 未分類の欄は、カテゴリの欄の下に出す。カテゴリが1つも無いときは、欄の見出しを出さずToDoだけを並べる                                                   |
| F-05 | カテゴリの欄はたためる。欄の見出しに「1 / 3 件済み」の形で、済んだ件数と全部の件数を出す。リストの上に、旅行全体の「4件済み · 残り6件」を出す         |
| F-06 | カテゴリの順は二人で同じものを見る。新しいカテゴリは一番下に足し、あとから順を変えられる                                                              |
| F-07 | カテゴリを削除すると、中のToDoも一緒に削除する。削除の前に、カテゴリの名前と消えるToDoの件数を出して確かめる。削除したものは戻せない                  |
| F-08 | リストの画面の追加の欄で、入れるカテゴリを選べる。選ばなければ未分類に入る                                                                            |

### 担当と期限

| ID   | 要件                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------- |
| F-09 | ToDoに担当を付けられる。担当は二人のどちらか、または未定。追加したときは未定                                         |
| F-10 | ToDoに期限（日付。時刻は持たない）を付けられる。付けなくてもよい。あとから変えられ、消せる                           |
| F-11 | 未完了のToDoの行に、担当の名前と期限（「10/5まで」）を出す。完了したToDoの行には、今と同じく誰が完了にしたかを出す   |
| F-12 | 「期限が近い」は、期限まで3日以内か、期限を過ぎた、未完了のToDo。ToDoの詳細の期限の欄に「あと3日」「期限切れ」を出す |
| F-13 | リストを「すべて」「自分の担当」「期限が近い」で絞れる。絞り込みは見ている端末だけのもので、相手の画面は変わらない   |
| F-14 | 担当・期限の変更と、期限が近づいたことでは、通知を送らない（元のF-15のまま）                                         |

### 予定との関連付け

| ID   | 要件                                                                                                                                                                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-15 | ToDoは、同じ旅行の予定1つと関連付けられる。完了か未完了かは問わない。1つの予定には、いくつでもToDoを関連付けられる                                                                                                                                       |
| F-16 | ToDoの詳細の「関連する予定」で、旅行の予定を日付ごとに並べた中から1つ選ぶ。取りやめた予定は選べない。あとから別の予定に変えられ、外せる                                                                                                                  |
| F-17 | 関連付けたToDoの行に、予定の日付と名前（「10/12 新幹線で京都へ」）を出し、押すと予定の詳細を開く。予定を取りやめていたら「取りやめた予定」と出す（元のF-16と同じ）                                                                                       |
| F-18 | 完了の印を付けても外しても、関連付けは変えない（元のF-12の「外したら、つながりも消す」を変える）                                                                                                                                                         |
| F-19 | 関連する予定が無い未完了のToDoには「新しく予定を作る」を出す。名前とメモを入れた状態で予定の追加の画面を開き、保存したら、作った予定とToDoを関連付ける。ToDoは完了にしない（元のF-10を変える）。予定の保存と関連付けは、サーバーの一つの書き込みで決める |
| F-20 | 予定を取りやめても、関連付けたToDoは変えない                                                                                                                                                                                                             |
| F-21 | 予定の詳細に「関連するToDo」の欄を出す。未完了を上、完了を下に並べ、済んだ件数と全部の件数を出す。未完了があれば「未完了のToDoが2件あります」と出す                                                                                                      |
| F-22 | 予定の詳細の「関連するToDo」で、完了の印を付け外しできる。行を押すとToDoの詳細を開く                                                                                                                                                                     |
| F-23 | 予定の詳細の「関連するToDo」から、名前を一行で入れてToDoを追加できる。追加したToDoは、その予定に関連付いた未分類のToDoになる                                                                                                                             |

## 非機能要件

- 保存の確かさ: カテゴリの追加・変更・並べ替え・削除と、ToDoのカテゴリ・担当・期限・関連付けの変更は、今ある保存と同じく、同じ要求の再送で二重に作られない。結果が分からないときは、同じ内容で送り直して確かめられる。
- 同時の変更: 二人が同じToDoやカテゴリを同時に変えたときは、今と同じく、後から保存した側に「相手が先に変更しました」と出す。
- 性能: 1つの旅行のToDoは最大200件、カテゴリは最大20個。リストは1回の読み込みで全部を出す。
- セキュリティ: 旅行の参加者でない人は、カテゴリを見ることも変えることもできない。担当にできるのは、その旅行の参加者だけ。関連付けられるのは、同じ旅行の予定だけ。
- 個人情報: 新しく持つのは、二人が書くカテゴリの名前と、担当（旅行の参加者のどちらか）、期限の日付。

## 正常系

1. 出発前に、本人が「出発前の準備」「行きたい所」のカテゴリを作る。前から書いてあったToDoは未分類の欄に見える。
2. 本人が「新幹線の切符を買う」を「出発前の準備」に入れ、担当をパートナー、期限を10月5日にし、予定「新幹線で京都へ」と関連付ける。
3. パートナーがリストを「自分の担当」で絞ると、「新幹線の切符を買う」が「10/5まで」の印つきで出る。
4. パートナーが予定「新幹線で京都へ」の詳細を開くと、「関連するToDo」に「新幹線の切符を買う」があり、「未完了のToDoが1件あります」と出る。切符を買って、その場で完了にする。
5. 本人が未分類の「嵐山の竹林」から「新しく予定を作る」を押し、日付を選んで保存する。しおりに予定が増え、「嵐山の竹林」は未完了のまま、行に「10/13 嵐山の竹林」が出る。
6. 旅行のあと、使い終わった「出発前の準備」を削除する。確かめの画面に「ToDo 3件も削除されます」と出て、押すとカテゴリとToDoが消える。

## 境界条件

| ID   | 条件                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------- |
| B-01 | カテゴリが0個のとき、リストは今と同じ見た目（見出しなしでToDoが並ぶ）に、「カテゴリを追加」を足したものになる   |
| B-02 | カテゴリの名前は1〜30字（前後の空白を除いて数える）。同じ名前のカテゴリも作れる                                 |
| B-03 | カテゴリは1つの旅行に最大20個。ToDoは今と同じ最大200件（カテゴリをまたいで数える）                              |
| B-04 | ToDoが0件のカテゴリは、欄の見出しと「0 / 0 件済み」を出す。確かめの画面は「ToDoはありません」と出して削除できる |
| B-05 | 期限は、過去の日付も、旅行の期間の外の日付も付けられる。期限を過ぎた未完了のToDoは「期限切れ」と出す            |
| B-06 | 「期限まで3日以内」は、日本の日付で数える。期限が今日なら「今日まで」、明日なら「あと1日」                      |
| B-07 | 絞り込んだ結果が0件のカテゴリの欄は出さない。全部が0件なら「当てはまるToDoはありません」と出す                  |
| B-08 | 今ある完了済みのToDoで、予定とつながっているものは、そのまま関連付けとして扱う                                  |
| B-09 | 旅行が終わったあとも、今のToDoと同じく、カテゴリ・担当・期限・関連付けを変えられる                              |

## 前提

- 旅行の参加者は二人で固定。担当の選択肢は、自分・相手・未定の3つになる。
- 予定は削除されず、取りやめになるだけ。関連付けた予定が無くなることは無い。
- 保存の再送・結果不明の確かめは、今ある端末に残す仕組み（ADR-0006）に載せる。

## 制約

- ToDoの画面はv3の画面一式に無い。見た目は採用した見本に合わせ、色と部品はv3にそろえる。
- 表と列は、今のDBの移し替え（Drizzleのマイグレーション）で足す。

## 対象範囲

- DB: カテゴリの表を足す。ToDoの表に、カテゴリ・担当・期限の列を足す。「予定とつながるのは完了のときだけ」の制約を外す。
- API（`apps/api`のplanningモジュール）: カテゴリの一覧・追加・名前の変更・並べ替え・削除。ToDoの追加と編集で、カテゴリ・担当・期限・関連する予定を受け取る。完了を外しても関連付けを残す。予定の保存で、元のToDoを完了にせず関連付ける。
- 契約（`packages/contracts`）: カテゴリの型。ToDoの型に、カテゴリ・担当・期限を足す。
- 画面（`apps/web`）: ToDoのリスト（`screens/todos`）、ToDoの詳細（`screens/todo-detail`）、予定を選ぶ画面、予定の詳細の「関連するToDo」（`screens/plan-detail`）、予定の追加の画面の説明の文（`screens/plan-form`。「保存すると、ToDoは完了になります」を変える）。
- 試験: API・画面の単体試験と、E2Eに「カテゴリを作る → ToDoを予定と関連付ける → 予定の詳細で完了にする」の流れ。
- 文書: `docs/requirements/trip-todo.md`と`docs/designs/trip-todo.md`の、変わる決まり（元のF-03・F-07・F-10・F-12・対象外）に、この文書への案内を足す。`docs/glossary.md`の「ToDo」を直し、「カテゴリ」「関連付け」を足す。

## 対象外

- 通知（担当になった・期限が近い）。時刻で動く処理は作らない。
- ホームに期限が近いToDoを出すこと。
- ToDoの並べ替え。
- 1つのToDoを複数の予定と関連付けること。
- カテゴリの色やアイコン。
- 旅行をまたいだカテゴリ（前の旅行のカテゴリを写す）。
- カテゴリを消してToDoだけ残す操作（削除の前に、ToDoを1件ずつ別のカテゴリへ移すことはできる）。

## 後方互換性・データ移行

- 今あるToDoは、未分類・担当は未定・期限なしになる。データの書き換えは要らない。
- 今ある完了済みのToDoの予定とのつながりは、そのまま関連付けになる（B-08）。
- 変わる動きが2つある。完了の印を外しても関連付けが残る（F-18）。ToDoから予定を作っても完了にならない（F-19）。
- ToDoのAPIの応答に欄が増える。古い画面は増えた欄を読まないので、apiを先に出しても表示は変わらない。ただしF-18・F-19の動きはapiを出した時点で変わる。出す順は設計で決める。

## 受け入れ条件

- F-01〜F-23、E-01〜E-11、B-01〜B-09を、API・画面の自動の試験で確かめる。
- E2Eで、一人が作ったカテゴリとToDoをもう一人が見られ、予定と関連付けたToDoを予定の詳細で完了にできる。
- 参加者でない人がカテゴリを読めず変えられないこと、別の旅行の予定・カテゴリ・人をToDoに付けられないことを、APIの試験で確かめる。
- カテゴリの削除で、中のToDoが一緒に消え、ほかのカテゴリと未分類のToDoは残ることを、APIの試験で確かめる。
- 品質コマンド（`npm run lint` / `npm run type-check` / `npm test` / `npm run build`）が通る。
- 結合検証環境で、スマートフォンの幅で、行の印（担当・期限・予定）が折り返しても読めることを手で確かめる。
