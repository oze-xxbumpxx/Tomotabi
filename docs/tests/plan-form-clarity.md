# 試験計画: plan-form-clarity（予定の追加と、予定の詳細の操作を分かりやすくする）

- 設計書: `docs/designs/plan-form-clarity.md`
- 実装計画: `docs/implementation-plans/plan-form-clarity.md`
- レベル: L2

## 何を確かめるか

直しはブラウザの画面だけで、APIとDBは変えない。単体の試験では、時刻の欄から送る値、画面に出る文字、ボタンの見た目の印（クラス）、保存したあとの行き先を確かめる。見た目の色と間隔は、結合検証環境で目で見て確かめる。

送る本文の形（時刻未定は`time: null`）は変えないので、冪等性と障害系の今の試験がそのまま守る。

## 観点

試験は今ある画面ごとの試験のファイルに足す（予定は`apps/web/tests/plans-screens.test.tsx`、支払いは`apps/web/tests/payments-screens.test.tsx`）。

### 時刻の欄（予定の追加・編集）

| 観点                     | 前提                           | 操作                                                    | 期待                                                                           |
| ------------------------ | ------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 最初から時刻の欄が出る   | 予定の追加を開く               | 開く                                                    | 時刻の欄があり、「時刻未定」のチェックは無い。欄の下に「空のままなら時刻未定」 |
| 空なら時刻未定で送る     | 予定の追加                     | 名前と種類だけ入れて保存                                | 送る本文が`time: null`                                                         |
| 入れた時刻を送る         | 予定の追加                     | 時刻に`09:30`を入れて保存                               | 送る本文が`time: "09:30"`                                                      |
| 入れかけの時刻は送らない | 予定の追加                     | 時刻の欄が入れかけ（`validity.badInput`が真）のまま保存 | 送らず「時刻を確認してください」                                               |
| 「消す」で空に戻す       | 予定の追加                     | 時刻を入れて「時刻を消す」を押す                        | 時刻の欄が空になり、焦点が時刻の欄に戻る。時刻が空のときは「時刻を消す」が無い |
| 編集で時刻を消す         | 時刻のある予定の編集           | 「時刻を消す」を押して保存                              | 送る本文が`time: null`                                                         |
| 編集で時刻を変えない     | 時刻のある予定の編集           | 名前だけ変えて保存                                      | 送る本文に`time`が無い                                                         |
| 時刻未定の予定の編集     | 時刻未定の予定の編集           | 開く                                                    | 時刻の欄が空で出る                                                             |
| 残した保留を読み直す     | 端末に`time: null`の保留がある | 予定の追加を開く                                        | 時刻の欄が空で出る                                                             |

### 種類とメモの補足（予定の追加）

| 観点               | 前提             | 操作               | 期待                                                                                          |
| ------------------ | ---------------- | ------------------ | --------------------------------------------------------------------------------------------- |
| 種類の見出し       | 予定の追加を開く | 開く               | 種類の見出しが「種類（どれか1つ）」                                                           |
| 種類を選ばずに保存 | 予定の追加       | 種類を選ばずに保存 | 今のまま「種類を選んでください」                                                              |
| メモの補足         | 予定の追加を開く | 開く               | メモの欄の下に「場所やURLはメモに書けます」があり、メモの欄に`aria-describedby`で結ばれている |

### 予定の詳細の操作

| 観点                       | 前提                       | 操作                     | 期待                                                                   |
| -------------------------- | -------------------------- | ------------------------ | ---------------------------------------------------------------------- |
| 別の日に移すの名前         | 予定の詳細                 | 開く                     | 「別の日に移す」のボタンがあり、「日の移動」は無い                     |
| 開く画面の見出し           | 予定の詳細                 | 「別の日に移す」を押す   | 見出しが「別の日に移す」                                               |
| 移したあとの知らせ         | 予定の詳細                 | 別の日を選んで移す       | 「別の日に移しました」                                                 |
| 取りやめの見た目           | 取りやめていない予定の詳細 | 開く                     | 「取りやめにする」が`btn-outline-danger`を持ち、ほかのボタンは持たない |
| 取りやめの確かめは今のまま | 予定の詳細                 | 「取りやめにする」を押す | 今と同じ確かめのダイアログが開く                                       |

### 予定から記録した支払いの戻る先

| 観点                         | 前提                          | 操作         | 期待                                                 |
| ---------------------------- | ----------------------------- | ------------ | ---------------------------------------------------- |
| 保存したら予定へ             | URLに同じ旅行の`planId`がある | 支払いを保存 | 予定の詳細（`/trips/{tripId}/plans/{planId}`）へ移る |
| 戻るリンクも予定へ           | 同上                          | 戻るを押す   | 予定の詳細へ移る                                     |
| ほかから開いたときは今のまま | URLに`planId`が無い           | 支払いを保存 | しおり（`/trips/{tripId}/itinerary`）へ移る          |
| 予定を確かめられないとき     | URLの`planId`の取得が失敗     | 戻るを押す   | しおりへ移る                                         |

## 回帰の範囲

- 予定の追加・編集の今の試験（名前・種類・日付の検証、送信中の固定、保留の送り直し）がそのまま通ることを確かめる。「時刻未定」のチェックを使っている試験は、新しい欄の形に直す。
- 予定の詳細の達成・予約のボタン（説明と押す前の確かめ）の試験がそのまま通ること。
- E2E（`npm run test:e2e`）は、`e2e/tests/m01-flow.spec.ts`で「時刻未定」や「日の移動」を探している所を新しい形に直して通す。

## 結合検証環境で見て確かめること

マージしたら結合検証環境に出し、スマートフォンの幅（375px）で見る。

- 予定の追加で、時刻の欄と2つの補足が読める大きさで出て、行が崩れていない。
- iPhoneのSafariで、時刻を入れたあと「時刻を消す」で空に戻せる（手元のiPhoneで見る。無ければ未確認と書く）。
- 予定の詳細で、「取りやめにする」が赤い文字と枠線で、ほかのボタンから少し離れている。明るい画面と暗い画面の両方で読める。
- 見るのに要るデータは、取りやめていない予定が1件ある旅行。無ければ点検用の旅行に予定を1件足す。
