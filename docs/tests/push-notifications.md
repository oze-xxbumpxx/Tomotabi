# 試験計画: push-notifications（相手の操作を知らせる通知）

- 前提となる設計書: docs/designs/push-notifications.md
- 要件: docs/requirements/push-notifications.md（F-・N-・E-・B-の番号はここ）
- 対象: API（購読の4つのAPI、ログアウトのガード、保存のあとに送る処理、11種類の保存からのイベント）、DB（2つの表と権限）、web（Service Worker、manifest、通知の設定の画面、旅行のメニュー、ホームの案内のカード、精算の画面、ログアウト）、E2E、手動確認。

## 観点の番号

- PU: 単体（DBを使わない）
- PD: 実DBのAPIの試験（`apps/api/tests/db/`。アプリのロール`app_runtime`で走らせる）
- PT: 送る部品の試験（本物の`HttpsPushTransport`を手元のHTTPサーバーに向ける）
- PW: 画面の試験（Vitest・Testing Library。APIとブラウザの通知の機能は模擬）
- PE: E2E（Playwright）
- PM: 手動確認

試験では、宛先の決まり（FCMとAppleのホストだけ）を変えない。送る処理の試験は、`PushTransport`だけを偽物に差し替え、偽物が受け取った要求（宛先・ヘッダー・暗号化した本文）を確かめる（論点の記録「手元と試験で、通知を送るところまでをどう確かめるか」の答え）。
