## 特性観点

- 権限: すべてのカテゴリの操作で、参加者でない人は403（A-I15）。別の旅行のカテゴリ・予定・人は付けられない（A-I14・A-U04・L-I04）。
- データ整合性: 削除はToDo・カテゴリ・受領が一つのトランザクション（A-I09・A-I10）。同時の追加と並べ替え（A-I07・A-I08）。一覧が同じ時点（A-I18）。
- 冪等性: カテゴリの追加・削除・予定の追加の再送（A-I03・A-I12・L-I09）。並べ替えと名前の変更も、受領の共通の仕組みで同じ応答を返す。
- 障害系: 対象外。外部のサービスを呼ばない。結果不明の送り直しは今の仕組みのまま（W-S15で経路を確かめる）。
- フロントエンド: 読み込み中と取得の失敗は今の部品のまま。完了の印を押した直後の見た目と、保存できなかったときに戻すこと（W-S12）。
- 防御性: Domainは不変条件（doneAtとdoneByの対、版の増え方）と、名前の上限（A-D01〜A-D10）。可変のオブジェクトは返さないので、防御的コピーは対象外。
