- 要件定義: `docs/requirements/trip-todo.md`
- 設計書: `docs/designs/trip-todo.md`
- 実装計画: `docs/implementation-plans/trip-todo.md`
- レベル: L3

## 何を確かめるか

ToDoの読み書きが予定と同じ決まり（同じ要求の再送で二重に作られない、相手が先に変えたら競合、参加していない旅行は403）で動くことと、「予定にする」で予定とToDoの完了が一度に決まることを確かめる。画面は見本どおりの文言・並び・リンク先を単体の試験で見て、5つのタブの幅は結合検証環境で目で見る。

外部のサービスを呼ばないので、障害系は「保存の結果が分からないときに同じ要求で確かめる」だけを見る（E-07）。

## 観点

### Domain（`apps/api/tests/domain/todo.test.ts`）

| 観点               | 前提                           | 操作                                      | 期待                                                      |
| ------------------ | ------------------------------ | ----------------------------------------- | --------------------------------------------------------- |
| 作る               | 名前「清水寺」                 | `create`                                  | 未完了、`planId`なし、メモなし                            |
| 名前の境界（B-02） | 空白だけ / 1字 / 100字 / 101字 | `update`（作るときはUseCaseの入力の検証） | 空白だけと101字は失敗、1字と100字は通る。前後の空白は除く |
| メモの境界（B-03） | 空 / 2000字 / 2001字           | `changeMemo`                              | 空はnull、2001字は失敗                                    |
| 完了にする         | 未完了                         | `complete(by, at, null)`                  | 完了、`doneBy`・`doneAt`が入る                            |
| 完了は何度でも同じ | 完了済み（Aが完了）            | Bが`complete`                             | 完了したのはAのまま、時刻も変わらない                     |
| 予定とつなぐ       | 未完了                         | `complete(by, at, planId)`                | `planId`が入る                                            |
| 戻す               | 予定につないだ完了             | `reopen`                                  | 未完了、`doneBy`・`doneAt`・`planId`がnull                |
| 戻すは何度でも同じ | 未完了                         | `reopen`                                  | 変化なし                                                  |

## 回帰の範囲

- 予定の追加（`plan-usecase.test.ts`・`plans-http.db.test.ts`・`plans-screens.test.tsx`）。`fromTodoId`なしの要求と要約が変わらない。
- 下のタブを使う画面の試験（`trip-tab-bar.test.tsx`・`screen-skeletons.test.tsx`・ホーム・しおり・履歴・精算の画面の試験）。
- 受領を使う書き込み全部（受領のcheckを置き換えるため）。`tests/idempotency/`と各`*-http.db.test.ts`。
- E2Eの今ある8本。

## 対象外

- 並べ替え・通知・予定の詳細から元のToDoへのリンク（要件の対象外）。
- 件数の上限を同時に超える場合（設計で1件超えてよいとしたため）。
