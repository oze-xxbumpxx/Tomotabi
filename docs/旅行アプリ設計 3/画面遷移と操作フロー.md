## 1. 画面の構成

旅行選択後の入口はホーム。主画面はホーム・しおり・記録・精算の4つとする案。予定詳細や入力フォームは、この4画面から開く補助画面であり、タブを追加しない。

| 主画面 | 開ける補助画面 | 主な役割 |
|---|---|---|
| ホーム | 予定詳細、支払い入力 | 今日の予定と現在の状況の把握 |
| しおり | 予定詳細、予定追加・編集、日の移動、支払い入力 | 予定の管理と達成・予約の記録 |
| 記録 | 記録詳細、支払い入力、対象予定の選択 | 発生した事実と訂正履歴の確認 |
| 精算 | 対象確認、精算履歴詳細 | 内訳の確認と受け渡し完了の記録 |

スマートフォンでは詳細・入力を十分な幅の補助画面として開く案。確認だけの短い操作は確認ダイアログとする。具体的なURLやコンポーネント構造はCursorで設計する。

## 2. アプリを開く

1. 未ログインならGoogleログインへ進む。
2. 許可されたアカウントであること、選択する旅行の参加者であることを確認する。
3. 有効な前回選択の旅行があれば、そのホームへ進む。未選択・アクセス不可なら旅行一覧へ進む。
4. 旅行がなければ旅行作成への導線を表示する。旅行作成フォームの詳細は今回の対象外。

ホーム上部から旅行一覧へ戻り、旅行を切り替えられる。タブの切り替えでは旅行を維持する。通知から開いた場合は認証・参加者確認後、対象の予定、記録、精算履歴へ進む案。削除・アクセス不可等で対象を開けない場合はその理由を表示し、アクセス可能な旅行一覧へ戻れるようにする。

## 3. ホームから予定を確認する

通常の流れ：ホーム → 今日の予定カード → 予定詳細 → 戻る → ホーム。

一覧を見たい場合：ホーム → 「今日のしおり」 → 今日の日付を選択したしおり → 予定詳細 → 戻る → しおり。

- 予定詳細では名前・種類・日付・任意時刻・メモと、取りやめ・達成・予約の状態を表示する。
- 詳細の戻り先は開いた画面とし、しおりからなら選択日と一覧の位置を維持する。
- 「達成を記録」「予約済みを記録」は条件を満たす場合に表示する。有効な記録が既にあれば状態と記録詳細への導線に置き換える。
- 登録成功後は予定詳細に留まり、状態を更新して短い完了表示を出す。相手にも通知する。
- 二人が同時に登録した場合は重複を作らず、既存の有効な記録を表示する。
- 取りやめ済みの予定への達成は不可。予約可能な種類なら、取りやめ済みでも予約記録は追加可能。

### 予定を追加・編集する

しおり → 「予定を追加」 → 名前・種類・日付・任意時刻・メモ → 保存 → 登録日のしおり。

予定詳細 → 「編集」 → 編集フォーム → 保存 → 更新後の予定詳細。

選択中の日付を追加フォームの初期値にする。通常編集は名前・時刻・メモを対象とする案。日の移動は別操作として旅行期間内の日付を選ぶ。種類は達成・予約の履歴がない場合のみ変更可能（合意済み）。取り消し済みの履歴も制限対象とする。支払いだけがある場合は変更できる。変更不可の場合は理由を表示し、正しい種類の予定の新規作成を案内する。

予定の取りやめは予定詳細から確認ダイアログを開き、実行後も詳細に留まって取りやめ状態を表示する。予約記録があれば実際の予約はキャンセルされないと伝える。

## 4. ホームから支払いを記録する

通常の流れ：ホーム → 「支払いを記録」 → 支払い入力 → 保存 → ホーム。

別の入口：予定詳細または記録タブ → 支払い入力 → 保存 → 開いた画面。

### 入力案

- 金額：日本円。正の整数。
- 支払った人：自分または相手。初期値は自分とする案。
- 負担の分け方：折半／支払者が全額／もう一人が全額／割合指定。
- 割合指定は1％単位。各人の表示名・割合・確定負担額を表示する。端数は支払いごとに支払者が負担する。
- 用途名：任意の提案。
- 関連予定：任意。予定詳細から開いた場合は選択済みとする案。

入力フォーム内に金額と負担の要約を表示し、通常の追加では別の確認画面を挟まない。保存成功後に戻り先のデータを更新し、「支払いを記録しました」と記録詳細への導線を表示する。

ホームの精算額の再取得に失敗した場合でも、支払いの保存成功は取り消さない。精算欄だけ取得失敗を表示する。

### 支払いを訂正する

記録 → 支払い詳細 → 「取り消す」 → 対象の確認 → 取り消し済みの詳細。

新しい支払いは「支払いを記録」から登録する。保存済み支払いの直接編集は設けない。既精算の支払いを取り消す場合は、過去の完了記録を書き換えず次の精算への調整になることを確認時に示す。

取り消し後に新規登録を中断しても、取り消し自体は成立したままとする。取り消しと入れ直しは別の操作であることを表示する。

## 5. ホームから精算する

通常の流れ：ホームの精算額 → 精算画面 → 「受け渡しを確認する」 → 対象確認 → アプリ外で受け渡し → 「受け渡し完了を記録」 → 精算画面。

1. 精算画面で最新の受け渡し方向・金額・対象明細・調整分を取得する。
2. 「受け渡しを確認する」で、その時点の対象と金額を固定した確認画面を開く。
3. 確認画面には渡す人・受け取る人・金額・対象明細を表示する。確認後に追加された支払いは次回へ回すことを補足する。
4. 利用者がアプリ外で受け渡しを終えたら「受け渡し完了を記録」を押す。この操作は送金を行わない。
5. 保存成功後は精算画面へ戻り、完了した金額と履歴への導線を表示する。現在の未精算分も再取得する。

確認中に追加分があれば、完了後も未精算額が残り得る。「すべて精算済み」と無条件に表示せず、今回の完了と残りを分ける。

### 例外の分岐

| 状態 | 画面の動き |
|---|---|
| 精算対象なし | 確認画面へ進むボタンを表示しない |
| 対象あり・差額0円 | 受け渡し不要と表示し、対象を確認して「受け渡し不要として精算を記録」とする案 |
| 確認後に新規支払い追加 | 確認中の対象・金額は変えない。追加分は次回へ |
| 対象支払いが取り消された | 受け渡し前なら最新内訳を再確認。元の確認金額を全額受け渡し済みなら、変更を明示して元の内容で完了を記録し、差額を次回へ |
| 相手が同じ対象を先に精算 | 既存の完了記録を表示して二重登録を防ぐ |
| 一部の対象だけ先に精算 | 対象変更を示して再確認。全件精算済みと誤表示しない |
| 完了記録の送信結果が不明 | 成功・失敗を断定せず、保存状態を確認する。再送で二重記録しない仕組みはCursorで設計 |

再確認を再送金の指示として表示しない。受け渡し後の対象取り消しは「受け渡し後の支払い訂正案.md」の合意に従う。完了記録と次回調整の整合性を守る。

確認画面から戻っただけでは精算完了にしない。確認対象の再利用・期限切れ・再開方法は未確定であり、特に外部送金サービスへ切り替えてアプリに戻る場合も、異なる対象へ無言で差し替えないことを受け入れ条件とする。

### 精算を取り消す

精算 → 履歴 → 最新の有効な精算の詳細 → 「完了記録を取り消す」 → 確認 → 取り消し済みの詳細。

取り消しは旅行ごとに最新の有効な1件のみ。確認には日時・金額・方向と、実際の返金は行われない旨を示す。操作後は現在の未精算分を再取得し、履歴を残す。古い精算は詳細閲覧できるが、取り消し不可の理由を表示する。

## 6. 戻る・中断・通信失敗

| 場面 | 共通方針の提案 |
|---|---|
| 閲覧画面で戻る | 開いた画面へ戻る。選択した日・絞り込みを維持する |
| 未変更のフォームを閉じる | そのまま戻る |
| 変更済みのフォームを閉じる | 入力を破棄するか確認する。自動保存は初期版の前提にしない |
| 入力エラー | 入力を保持して該当項目の近くに理由を表示 |
| 保存中 | 進行状態を表示し、連打を防ぐ |
| 明確な保存失敗 | 入力を保持して再試行できるようにする |
| 保存結果が不明 | 最新状態を確認する導線を表示。通知の有無で成否を判断しない |
| オフライン | 更新操作は不可。実装する場合は保存済みしおりのみ閲覧可能 |

## 7. 基本設計の確認シナリオ

Cursorでは以下を実装・検証の起点とし、具体的なテスト方式は詳細設計で決める。

1. ホームから予定を開き、戻るとホームへ戻る。しおり経由なら同じ日へ戻る。
2. 時刻未定の予定を登録でき、0時の予定として表示されない。
3. 達成・予約を二人が同時登録しても、それぞれ有効な記録は1件となる。
4. ホームから予定に紐づかない支払い、予定詳細から関連付き支払いを登録できる。
5. 10,000円を本人70％・相手30％で登録すると、支払者に応じた受け渡し方向・金額になる。
6. 本人が支払った1,001円の折半が2件なら、相手から本人への受け渡しは1,000円になる。
7. 精算確認後に追加された支払いは今回の対象に入らず、完了後の未精算分に残る。
8. 同じ対象の精算を二人が同時に完了しても、記録は重複しない。
9. 最新の有効な精算を取り消すと履歴が残り、前の有効な精算が取り消し可能になる。
10. データ保存後の通知失敗が、保存自体の失敗として表示されない。

残論点：確認内容の再開・期限。未合意の入力項目や画面文言も、本書の提案と合意済み業務ルールを区別して扱う。

11. 元の確認金額を受け渡した後で対象支払いが取り消されても、元の内容で完了を記録し、取り消し分を次回へ一度だけ反映できる。取り消しが完了記録の直前・直後のどちらでも計算結果が一致する。

精算取り消しと支払い取り消しを組み合わせた計算ルールは2026-09-06合意済み。「精算取り消しの整合性確認.md」の受け入れ条件を参照する。
